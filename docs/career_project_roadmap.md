# MiniGPT 求职项目总路线图

更新日期：2026-08-25

## 1. 项目使命

本项目的目标不是继续横向堆叠功能，也不把教学用字符模型包装成通用大模型，而是构建一条
可解释、可训练、可评测、可部署、可复现的个人 LLM/Agent 工程主线：

```text
Transformer 原理实现
→ 真实预训练模型的监督微调
→ 纯文本多轮对话
→ 工具调用与文档检索
→ 评测驱动的数据和架构迭代
→ 可观测的模型服务
→ Word/PDF 等办公文档能力
→ 后续可选的图像与语音能力
```

公开求职版本首先交付可靠的纯文本 Agent。成年人创作能力仅作为未来私有、显式启用、
可拔插的领域 Adapter 研究，不进入当前数据、默认模型、公开 Demo 或近期里程碑。

## 2. 求职定位

项目最终应同时提供三层证据，但只围绕一条主线叙事：

1. **模型原理**：能够解释并实现 Causal LM、Attention、训练状态、采样和 KV Cache。
2. **训练与评测**：能够把失败类型转化为数据，完成 response-only SFT/LoRA，并用冻结
   测试集证明改进。
3. **Agent 工程**：能够实现受限工具、RAG、引用、追踪、服务、文档产物和性能验收。

推荐的一句话介绍：

> 一个面向单卡环境的评测驱动 LLM/Agent 系统，覆盖从零 Transformer、监督微调、工具
> 调用、检索引用到可观测服务的完整闭环。

## 3. 已有基线

截至 2026-08-25，仓库已有以下可复现证据：

- 818,432 参数的字符级 Decoder-only MiniGPT；Tiny Shakespeare 固定预算正式基线。
- FP32、FP16、BF16和学习率调度单变量实验。
- Greedy、Temperature、Top-k、Top-p、固定 seed、普通生成和 KV Cache。
- Qwen2.5-0.5B response-only SFT 与 PEFT LoRA，Adapter 保存和恢复一致性。
- MiniGPT/Hugging Face/LoRA 统一聊天接口和 FastAPI 服务。
- 工具注册、Schema 校验、超时、确认、重复调用保护、Agent trace。
- 100 条 Agent 评测集以及 0.5B LoRA、3B 4-bit 两条真实基线。

当前最重要的系统基线：

| 指标 | 0.5B + 现有 LoRA | 3B 4-bit Base |
|---|---:|---:|
| 工具选择准确率 | 76.9% | 83.1% |
| JSON 合法率 | 100.0% | 100.0% |
| 参数准确率 | 72.5% | 82.5% |
| 最终任务成功率 | 37.0% | 52.0% |
| 不必要工具调用率 | 74.3% | 51.4% |
| 端到端 RAG Recall@5 | 18.2% | 50.0% |
| 引用正确率 | 0.0% | 40.9% |
| 异常恢复率 | 75.0% | 75.0% |

现有 LoRA 只有 16 条课程问答训练数据，而 Agent 评测关注工具选择、检索触发和引用；
训练目标与评测目标没有对齐。这是下一阶段的首要问题，而不是立即更换向量数据库。

## 4. 硬件、磁盘和下载约束

### 4.1 当前约束

- 本地 GPU：RTX 4060 Laptop，8GB VRAM。
- 项目盘：D 盘；2026-08-25 检查时剩余约 158.9GB。
- 本阶段新增数据、模型、Hugging Face 缓存和实验产物合计不得超过 **40GB**。
- 日常目标控制在 **32GB** 内，至少保留 8GB 缓冲用于临时文件和失败恢复。
- 不在 C 盘下载模型或数据，不依赖默认用户目录缓存。

### 4.2 建议预算

| 类别 | 软预算 | 硬上限 | 说明 |
|---|---:|---:|---|
| Base 模型与 Tokenizer | 10GB | 14GB | 只保留实际使用的 0.5B/3B 主线模型 |
| 纯文本语料 | 8GB | 12GB | 先使用小而可审核的数据，不下载全量大语料 |
| LoRA Adapter/Checkpoint | 4GB | 6GB | 保留 best/latest 和关键对照，不保留所有 step |
| Hugging Face/构建缓存 | 5GB | 6GB | 训练完成后按清单清理可再生缓存 |
| 评测、日志和报告 | 2GB | 2GB | JSONL、图表、轻量报告 |
| 临时缓冲 | 3GB | — | 不计入稳定资产，但计入 40GB 硬上限 |

所有下载前必须记录：来源、许可证、预计大小、目标目录、SHA/版本、用途和删除方式。
下载完成后记录实际大小。超出单项软预算时先停止，不自动继续拉取分片。

### 4.3 推荐本地目录

```text
D:\mini-gpt-from-scratch\data\raw\          原始语料
D:\mini-gpt-from-scratch\data\processed\    清洗和切分结果
D:\mini-gpt-from-scratch\hf_lora\artifacts\ Adapter
D:\mini-gpt-from-scratch\runs\               训练实验
D:\mini-gpt-from-scratch\.cache\huggingface\ 模型和数据缓存
```

这些目录中的大文件不得提交 Git。启动训练/下载时应显式设置 `HF_HOME`、
`HF_DATASETS_CACHE` 和模型输出目录到 D 盘。

## 6. 阶段路线与验收

### P0：项目治理与冻结基线（已完成）

目标：把“继续开发”变成可审计的研究过程。

工作项：

- 建立本总路线图和研究日志。
- 固定现有 0.5B/3B 报告为 `baseline-v1`。
- 定义实验编号、单变量原则、资源记账和结论口径。
- 将现有 100 条已经用于调研的用例定位为开发集候选。
- 后续新建不反复查看的冻结测试集。

验收：

- 路线图、研究日志和 README 入口存在。
- 所有真实数值均可追溯到配置、报告或命令。
- “计划值”和“实测值”明确区分。

需要掌握：训练集、验证集、开发评测集和冻结测试集为什么不能混用；为什么只看 Loss
不能证明 Agent 能力提升。

### P1：评测系统 v2 与失败分层（已完成）

目标：先让指标告诉我们应该改数据、Prompt、路由、检索还是生成。

工作项：

- 将端到端 RAG 指标拆为检索触发 Precision/Recall、条件 Retriever Recall@1/3/5、
  端到端 Recall@5、Citation Precision/Recall 和 Unsupported Claim Rate。
- 新建独立开发集，覆盖 direct、tool、retrieval、multi-step、recovery 和安全边界。
- 设计 150～300 条冻结测试集；只有版本候选完成后才能运行。
- 为主要比例指标增加 bootstrap 95% 置信区间。
- 保存逐 case 失败标签和回归差异。

当前进度：EVAL-001 已完成指标拆分并使用两份历史预测重算。EVAL-002 已建立 100 条 dev、
150 条 frozen-test candidate、SHA-256 manifest、bootstrap 置信区间、逐 case 回归和 CI
离线 smoke。3B 在已触发检索时的条件 Recall@5 为 91.67%，但触发 Recall 仅为 54.55%，
确认下一步优先改进 route decision。冻结集机器验收已通过，并由项目所有者李林知于
2026-08-25 签发为 `agent-frozen-test-v1`。详细记录见 `docs/research_log.md`。

验收：

- 能区分“没调用检索”“检索没召回”“召回后没引用”三类错误。
- 评测中断可恢复、结果不可静默覆盖、用例与训练数据零精确重叠。
- 0.5B smoke 子集进入 CI；3B 全量保留本地回归。

需要掌握：确定性评分、人工评分和 LLM-as-a-judge 的边界；置信区间与单次点估计的差别。

### P2：纯文本 Agent 路由 v2（已完成，引用约束待 P6 收口）

目标：在不训练新模型前，先验证系统策略能解决多少问题。

工作项：

- 对比单阶段自由工具调用和两阶段 route decision。
- 改进工具描述、no-tool 规则和检索触发协议。
- 引用必须来自工具实际返回的 citation 白名单。
- 参数 Schema 失败最多自动修复一次；工具瞬时失败有限重试。
- 增加 max steps、timeout、重复调用、确认和 trace 回归测试。

验收目标（须以实测报告为准，不提前宣称达到）：

- JSON 合法率不低于现有 100%。
- 3B 单工具任务成功率达到或超过 85%。
- 3B 不必要工具调用率从 51.4% 显著下降。
- 3B 检索触发和引用指标显著提高。

实测状态（2026-08-25）：在相同 0.5B 课程 LoRA 的 100 条 dev 对照中，heuristic router
将任务成功率从 37% 提高到 65%（paired 95% CI +19～+38pp），不必要工具调用率从
74.29% 降到 0%，端到端 RAG Recall@5 从 18.18% 提高到 45.45%。最终 3B 候选在 frozen
上的不必要工具调用率为 0%、检索触发 Precision/Recall 为 100%/93.18%，但单工具成功率
70.91%，未达到原定 85%；citation 白名单仍列为 P6 首批工作。详细记录见
`docs/p2_p5_completion.md`。

需要掌握：Prompt 改进为什么属于系统改进而不是权重能力提升；规则路由和模型路由的取舍。

### P3：Agent SFT 数据管线（已完成）

目标：让监督数据直接对应当前失败类型。

第一版建议 2,000～4,000 条高质量轨迹：

| 数据类型 | 建议数量 | 对应指标 |
|---|---:|---|
| 直接回答和 no-tool hard negatives | 500～1,000 | 不必要工具调用率 |
| 单工具调用 | 400～800 | 工具选择、JSON 合法率 |
| 参数困难样本 | 300～500 | 参数准确率 |
| 检索、引用和无依据回答 | 500～1,000 | 触发、Recall、Citation |
| 多步骤和失败恢复 | 200～500 | 最终成功率、恢复率 |
| 安全边界和越权拒绝 | 100～300 | 安全回归 |

工作项：

- 定义包含 `assistant tool call`、`tool result`、最终回答的多轮 JSONL Schema。
- Assistant 的工具调用和最终文本参与 Loss；system/user/tool result/padding 设为 `-100`。
- 统计每个角色的有效监督 Token，防止 Mask 配置与意图不一致。
- 做精确去重、近似去重、来源/许可证登记、训练评测污染检查。
- 合成数据只能作为候选；执行型样本由真实工具校验，关键样本人工审核。
- 先用小样本 smoke，确认链路后再扩充，不一次下载大语料。

验收：

- 数据卡、版本、hash、统计和审核记录完整。
- 训练/验证/dev/test 互不混用。
- 可从失败标签反查相应训练数据类别。

实测状态（2026-08-25）：已建立 2,400 条 train + 300 条 validation 的 Agent v1.1 多轮
轨迹，五类各 540 条；所有 assistant turn 参与 Loss，system/user/tool/padding 均 mask。
2,700 个 user prompt 全部唯一，与 250 条 dev/frozen 的精确重叠和高相似近似重叠均为 0。
v1.0 的工具暴露与重复数据失败被保留为反例，详见 `docs/research_log.md`。

需要掌握：response-only loss、角色 Mask、Token 加权梯度累积、数据质量和灾难性遗忘。

### P4：0.5B LoRA 快速迭代与 3B QLoRA 主实验（已完成，条件验收）

目标：证明监督微调，而不是仅凭主观样例声称模型变好。

建议实验矩阵：

| ID | 模型 | 路由 | Agent SFT | 目的 |
|---|---|---|---|---|
| E0 | 0.5B Base | v1 | 无 | 最弱基线 |
| E1 | 0.5B Base | v2 | 无 | 路由收益 |
| E2 | 0.5B LoRA | v1 | 有 | 纯训练收益 |
| E3 | 0.5B LoRA | v2 | 有 | 快速完整方案 |
| E4 | 3B 4-bit Base | v2 | 无 | 模型规模收益 |
| E5 | 3B QLoRA | v2 | 有 | 单卡最终主模型 |

工作项：

- 0.5B 用于数据、Mask、LR、LoRA rank 和 target modules 快速迭代。
- 3B 在配方稳定后做 QLoRA；不在 8GB GPU 上盲目全参数微调。
- 训练中记录有效 Token、Loss、梯度范数、LR、tokens/s、显存、耗时和最佳 step。
- 对通用问答、工具、RAG 同时回归，防止领域 SFT 造成能力退化。
- 最少保留 Base、最佳 LoRA 和最终恢复 Adapter 三份关键产物。

验收：

- Adapter 保存前后/重新加载后的输出或 logits 一致性通过。
- 至少完成 Base、Router-only、SFT-only、Router+SFT 四组可归因对照。
- 冻结测试集只用于候选版本验收，报告包含置信区间和失败样例。

需要掌握：LoRA 的 rank/alpha/target modules；QLoRA 的量化基座与可训练 Adapter；
为什么训练 Loss 降低不等于任务成功率提高。

实测状态（2026-08-25）：0.5B v1.1 LoRA 改善 RAG 和引用但总体任务从 Router-only 的
65% 变为 61%，因此未选为默认。3B NF4 QLoRA 峰值 allocated VRAM 4,028.70MiB，dev
任务成功率 78%，随后唯一一次 150 条 frozen 终测为 74%（95% CI 67.33%～81.33%）、
RAG Recall@5 88.64%。Frozen 单工具 70.91%、multi-step 0%、recovery 0%，没有达到全部
目标。量化重载通过独立加载和 250 条端到端运行验收，但没有通过严格 logits 一致性，边界
记录在 `docs/p4_3b_qlora_training_summary.md`。

### P5：RAG v2 与知识型文本 Agent（已完成组件对照）

目标：建立能回答仓库、技术文档和用户知识库问题的可靠纯文本 Agent。

工作项：

- 先保留词法检索强基线，再加入小型本地 embedding 模型。
- 分离 chunking、embedding、retrieval、rerank 和 answer generation 的指标。
- 支持 Markdown、TXT、代码和后续 Office/PDF 抽取后的统一文档对象。
- 增加 hybrid retrieval、metadata filter 和可选轻量 reranker。
- 引用必须可追溯到文档 ID、路径和片段。
- 文档无答案时明确表达无依据，不用模型参数记忆冒充检索结果。

验收：

- 同一语料上提交 lexical、dense、hybrid 三条对照。
- Retriever 指标和端到端回答指标分开报告。
- 新增模型与索引仍满足 40GB 总上限。

需要掌握：向量相似度、chunk size/overlap、Recall/MRR、reranker、上下文污染和引用忠实度。

实测状态（2026-08-25）：已实现 lexical、dense、hybrid 与 weighted RRF，并在 22 条 dev
检索用例、15 篇文档上对照。三者 Recall@1/3/5 和 MRR 均为 100%；lexical/dense/hybrid
平均延迟分别为 0.278/13.851/13.295ms。由于当前语料没有精度差异，继续以 lexical 为
默认，dense/hybrid 保留为可插拔实现。BGE small 中文模型实际占用 183.35MiB。

### P6：可观测服务与对话产品（已完成可靠性与服务骨架，条件验收）

目标：把评测通过的 Agent 变成可现场演示和负载验证的服务。

工作项：

- SSE 流式输出、请求取消、会话上下文、上下文预算和摘要压缩。
- Base/LoRA、direct/tool/retrieval 路径可视化。
- 请求 ID、首 Token 延迟、总延迟、Token 数、工具耗时和 finish reason。
- 并发限制、队列、超时、CUDA OOM 处理和模型恢复。
- 干净的 Web Demo：聊天、引用、工具轨迹、模型切换和示例问题。
- Docker 真实模型镜像/挂载验收和生成端点负载测试。

验收：

- 不只压测 `/health`，还要报告真实短/中/长生成的 TTFT、tokens/s、p50/p95。
- 服务错误不泄露内部路径、Prompt、私有数据或完整敏感日志。
- 一条命令可启动本地 Demo。

需要掌握：prefill/decode、TTFT、吞吐/延迟权衡、并发排队、KV Cache 与上下文长度。

实测状态（2026-08-25）：已完成计划完成门禁、一次保守参数修复、只读工具有限重试、
协作式取消、上下文预算和引用白名单；服务新增同步/SSE Agent 端点、run ID、并发上限、
取消、聚合指标与本地 `/demo`。同一 100 条 3B dev 对照中，任务成功率由 78% 到 79%
（paired 95% CI 0～+3pp），multi-step 由 13/15 到 14/15；参数、单工具和恢复无改善，
Citation Recall 由 63.64% 降到 59.09%。因此工程可靠性完成，模型效果只做条件验收。
SSE 当前是阶段事件而非逐 Token 推送，取消也不能抢占进行中的 HF generate；真实生成
TTFT/tokens/s/p95 和 Prometheus 仍是后续性能子阶段，不能写成已完成。

### P7：Word/PDF 等办公文档能力（已完成）

目标：Agent 能生成可验证的实际文件，而不仅在聊天中输出 Markdown。

第一批工具：

- `create_docx`：根据结构化大纲生成 `.docx`。
- `create_pdf`：由受控模板生成 PDF，或从已验证的文档转换。
- `read_docx` / `read_pdf`：抽取文本、标题、表格和基础 metadata。
- `summarize_document`：对长文档分块总结并保留引用。
- `export_report`：把一次评测/研究日志生成正式报告。

工具约束：

- 所有输出写入显式工作目录，不允许任意路径覆盖。
- 文件名、扩展名、大小和页数有上限。
- 创建后执行“结构校验 + 渲染 + 视觉检查”，不能只以 Python 成功退出为验收。
- 写入、覆盖、打开外部文件等副作用走确认机制。
- 文档内容和来源进入 trace，但敏感正文默认脱敏。

验收：

- 从对话生成一份包含标题、目录、表格、页码和引用的 Word/PDF 项目报告。
- 重新读取产物，检查关键字段；渲染页面无截断、重叠或乱码。
- 加入不少于 20 条工具选择/参数/产物验证用例。

需要掌握：工具 Schema、可恢复副作用、文档对象模型、PDF 固定布局和视觉 QA。

实测状态（2026-08-25）：已实现六个受控工具，并用显式 `DocumentWorkspace` 限定文件名、
扩展名、10MB 上限、目录穿越和覆盖确认。最终项目报告 DOCX 为 39,702 bytes、2 页，
PDF 为 126,675 bytes、2 页；两者均写后回读，所有 4 个渲染页面完成逐页视觉检查。检查中
实际发现并修复 PDF CID 字体的英文异常字距和列表空框，最终无截断、重叠、乱码或表格越界。
P7 面向结构化报告，不把任意模板编辑、修订批注、OCR 或扫描件理解包装成已有能力。

### P8：从零训练线现代化（已完成组件与受控短预算实验）

目标：保持教学清晰度，同时展示对现代小模型训练架构的理解。

候选单变量改进：

- Character Tokenizer 与 BPE 对照。
- Learned absolute position 与 RoPE 对照。
- LayerNorm/GELU 与 RMSNorm/SwiGLU 对照。
- 手写 Attention 与 PyTorch SDPA 对照。
- 独立 QKV 与 fused QKV 对照。
- 普通 batch 与 sequence packing 对照。

验收：

- 每个改动在相同 Token/FLOPs 或相同时间预算下比较。
- 同时报告验证 Loss/BPB、tokens/s、峰值显存和生成样例。
- 不把小模型、单 seed 结论外推为通用规律。

需要掌握：现代架构选择改变了什么数学路径和系统代价；nanochat 类项目为什么强调统一
训练配方、BPB、吞吐和可复现实验。

实测状态（2026-08-25）：已在同一 MiniGPT 中实现可选 RoPE、RMSNorm、SwiGLU、SDPA 和
fused QKV，旧配置默认行为不变；训练、评估、生成、服务和 KV Cache 均支持新配置。另有
确定性教学 BPE 与 sequence packing。300 步固定 Batch 实验中 SDPA 同参数吞吐 +21.40%，
fused QKV +15.55%，组合现代架构 -26.13%；所有变体验证 Loss 因固定 Batch 过拟合而上升，
因此不签发精度提升。BPE Token 数减少 48.656% 且 roundtrip 正确，正式相同字符预算 BPB
实验仍待完成。

### P9：图像与语音多模态扩展（基础闭环已完成）

目标：以工具化和模块化方式增加模态，不破坏纯文本核心。

图像路线：

- 图片上传、格式/大小校验、OCR、caption、文档图片问答。
- 使用独立视觉编码器或本地小型 VLM，先做只读理解，不立即做图像生成。
- 新建图文 grounded QA 评测，区分 OCR 错误、视觉理解错误和语言生成错误。

语音路线：

- ASR：语音输入转文字，记录字错率和实时率。
- TTS：文本回答转语音，支持取消和流式播放。
- 明确分离 ASR、LLM、TTS 三段延迟和错误。
- 优先选择小型、量化、本地可运行模型，继续遵守 40GB 总预算；如需扩容必须先修改预算。

验收：

- 图像：能读取截图/扫描件，回答时引用可定位区域或抽取文本。
- 语音：完成语音输入到语音回答闭环，并分别报告 ASR、LLM、TTS 性能。
- 文本模式测试无回退。

需要掌握：模态编码器、投影层、OCR/ASR/TTS 的独立评测，以及级联错误传播。

实测状态（2026-08-25）：已实现受控媒体工作区、base64 上传、图片元数据/OCR、WAV ASR、
离线 TTS、三个 Agent 工具、五个服务接口和 ASR/LLM/TTS 分段 pipeline。真实 TrOCR small
单行印刷体 smoke CER 0%，Whisper tiny 对系统合成短英文字符错误率 9.52%；OCR/ASR 热路径
约 75.56/74.09ms，模型缓存 383.99MiB，全部在 D 盘。复杂截图、表格、中文扫描件、真实
噪声语音和真实 3B voice-to-voice p95 尚未验收，不视为联合多模态模型。

## 7. 实验和结论规范

### 7.1 一次只回答一个问题

正式实验必须描述：

```text
研究问题
假设
基线
唯一主要变量
受控变量
训练/评测预算
主要指标
回退指标
资源代价
结论和限制
```

如果同时更换模型、Prompt、数据和路由，只能称为“系统版本对比”，不能把全部提升归因于
其中一个变量。

### 7.2 关于 Top-k 的特别说明

Top-k 是解码采样参数，不是训练精度旋钮。提高 `k` 会扩大候选 Token 集，通常增加
多样性，也可能增加错误；降低 `k` 通常更保守，但可能导致重复。只有在固定模型、Prompt、
seed/采样次数和评测集的条件下，某个任务指标实测提高，才能写“该配置在本评测上提升
了 X”，不能写“提高 Top-k 必然提高精度”。工具和确定性任务默认优先使用 greedy；
创作任务才重点比较 Temperature/Top-k/Top-p。

### 7.3 实验状态

- `planned`：只有假设，没有结果。
- `running`：正在运行，不做结论。
- `completed`：原始结果完整，可复现。
- `invalid`：存在污染、预算不一致、程序错误或指标口径变化。
- `superseded`：实验有效，但已被新基线替代。

失败或无提升的实验也保留，它们同样是研究证据。
