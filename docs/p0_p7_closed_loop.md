# MiniGPT P0–P7 阶段闭环审计

- 作者：李林知
- 日期：2026-08-25
- 审计范围：P0 项目治理至 P7 受控文档能力

## 1. 闭环结论

我已经把项目从“能训练一个小型 Decoder-only Transformer”推进为一条可解释、可训练、
可冻结评测、可检索引用、可调用工具、可观测并能交付真实 Word/PDF 文件的纯文本 Agent
主线。P0–P7 的关键价值不是功能数量，而是每个重要判断都有代码、测试、版本化评测或实际
产物作为证据。

这仍不是生产级通用 Agent。P0–P5 frozen 的任务成功率为 74%，multi-step 和 recovery
均为 0%；P6 只在 dev 上把 multi-step 从 13/15 提高到 14/15，总任务仅 +1pp 且置信区间
包含 0，引用召回还下降。我的验收结论是“工程闭环完整、生产级未完成”。

## 3. 模型指标与系统指标分开看

P0–P5 唯一一次 `agent-frozen-test-v1` 结果保持不变：任务成功率 74.00%、JSON 合法率
100%、不必要工具率 0%、端到端 RAG Recall@5 88.64%、单工具 70.91%、multi-step 0%、
recovery 0%。我没有为 P6 重跑或反复查看 frozen 来制造更好数字。

P6 在 100 条 dev 上为任务 79%、multi-step 93.33%（14/15）、单工具 80%、参数 80%、
recovery 75%。和保存的 P4 dev 基线相比，任务 +1pp（paired 95% CI 0～+3pp），只新增
`ms-007` 一个成功案例。Citation Recall 从 63.64% 降到 59.09%，所以我没有给 P6 贴上
“模型精度明显提升”的标签。

系统侧则形成了明确提升：计划完成门禁、参数单次修复、只读有限重试、协作式取消、上下文
预算、引用白名单、SSE 进度、并发上限和聚合指标都有独立测试。系统不变量可以是强结论，
模型统计提升只能是弱结论，这两类证据不能混在一起。

## 4. P7 真实交付闭环

P7 不以“库函数没有报错”为验收。最终报告由可复现脚本调用同一文档工具契约生成，DOCX
写后回读得到 27 个段落和 1 个表格，PDF 回读得到 2 页。随后 Word 转 PDF 和独立 PDF
分别渲染为 2 页 PNG，我逐页检查了共 4 个页面。

视觉检查实际发现并修复了两个自动结构校验看不见的问题：CID 字体的英文异常字距、列表
符号显示为空框。最终两种格式均无截断、重叠、乱码和表格越界。这证明文档 Agent 的验收
必须包含“Schema → 路径安全 → 写入 → 回读 → 页面渲染 → 视觉检查”的完整链路。

## 5. 工程质量门禁

收口门禁包括 Ruff format、Ruff lint、mypy、Dev/Frozen split validation、pytest 与分支
覆盖率。最终工作树 Ruff 与 split validation 通过，mypy 对 67 个 source files 报告 0
issue；全量测试 227 passed，覆盖率 71.36%（门槛 60%）。唯一警告来自 Starlette
TestClient 的上游弃用提示。

## 6. 是否符合最初预期

符合的部分：

- 我能从 Attention、Causal LM、SFT、LoRA/QLoRA 讲到 Agent 编排、RAG、评测治理和服务。
- 项目有真实失败实验、冻结结果、paired CI 和没有被美化的负指标。
- 纯文本 Agent 有对话、检索、工具、服务和真实办公文档交付能力。
- 新增依赖约 5.7MiB，资源仍远低于 40GB，且全部产物位于 D 盘。
- 结果可从代码、JSON 报告、第一人称日志和实际文件四条路径交叉验证。

尚未符合“完美结果”的部分：

- 没有 token-level streaming、可抢占 GPU 取消、长期记忆和生产级监控。
- 单工具和参数能力仍未达到理想阈值，引用完整性没有改善。
- P7 只覆盖结构化报告，不是通用 Office 自动化或 OCR 系统。
- 图像、语音等多模态仍按路线图放在 P9，未提前稀释纯文本主线。

P0–P7 已形成一个可审计的 AI/LLM 研究工程，但应将其表述为“可复现的端到端候选与可靠性
骨架”，不应使用“生产级通用智能体”之类无法由证据支持的结论。

## 7. 技术说明顺序

先用冻结失败说明为什么不能只看 validation loss，再说明两阶段路由和 QLoRA 如何在 8GB
显存内形成候选；然后展示 P6 如何把 multi-step、参数、恢复和引用问题变成系统约束；最后
通过 `/demo` 观察 trace，并用 P7 导出这份报告。对于系统不足，应明确指出 +1pp 的
置信区间、引用回退、协作式取消边界和 frozen 未重跑原则，从而保持研究可信度和工程边界。
