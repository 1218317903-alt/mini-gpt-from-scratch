# Agent SFT v1 数据卡

- 作者：李林知
- 日期：2026-08-25
- 版本：`agent-sft-v1.1`
- 规模：训练 2,400 条，验证 300 条
- 存储位置：D 盘项目目录 `hf_lora/data/agent_v1`

## 我为什么构造这套数据

我原来的 LoRA 数据只覆盖单轮问答，无法教模型学习“判断是否调用工具—生成结构化参数—读取工具结果—形成最终回答”这一完整轨迹。P3 的目标不是继续堆普通问答，而是把监督信号对准 Agent 最薄弱的行为边界。

我选择了五类均衡样本：直接回答、计算器、当前时间、带引用检索、失败后重试，各 540 条。这样既能教模型调用工具，也能教它在不需要工具时克制调用。2,700 个用户 Prompt 全部唯一；每条数据都带有可追溯 ID、类别、合成标记和随机种子。

## 轨迹与标签策略

工具样本使用多轮 `system → user → assistant(tool call) → tool → assistant(final)`；恢复样本再加入一次错误结果和重试。工具调用统一为项目运行时使用的严格 JSON 协议。为了与 P2 路由后的真实推理分布一致，每类工具样本只展示该路由允许的工具 schema；直接回答样本不注入工具说明。

v1.0 曾错误地给所有样本展示三个工具的完整 schema，且部分 Prompt 在训练/验证间重复。它虽然把验证 loss 降到 0.00188，却让开发集任务成功率从 65% 回落到 56%。我保留了失败产物，并在 v1.1 中修复 schema 分布不一致和内部重复问题。

训练时我只给所有 `assistant` 片段计算 loss。`system`、`user` 和 `tool` 返回仍保留在注意力上下文中，但 labels 为 `-100`。这使模型学习“应该输出什么”，而不会被迫复述用户问题或工具返回。

## 污染控制

构建脚本会同时检查开发集和冻结集的用户问题，但不会读取冻结集模型结果或据此调参。检查包含：

- 小写字母数字归一化后的精确匹配；
- 字符三元组 Jaccard，相似度阈值 0.80；
- 训练与验证合并后的内部 Prompt 去重；
- 固定 seed `20260825`，确保数据可重建。

原始检查结果在 `contamination_report.json`。如果发现精确或近似重合，构建命令会返回失败，避免把评测答案混入训练。

## 已知局限

这是一套行为格式训练数据，不是通用知识预训练语料。它的事实内容是合成的，不能用来证明模型知识增加；它主要用于验证工具选择、参数格式、引用和恢复行为。当前类别均衡也不等于真实线上分布，后续应使用匿名化真实失败样本做难例增量，并保持冻结集隔离。

## 许可与隐私

数据由本项目确定性生成，不包含个人信息、真实企业秘密或外部受版权保护文本。引用中的项目、团队和文档 ID 均为虚构内容。
